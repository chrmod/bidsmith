An **ad** is the creative that runs inside an ad group. Bidsmith
supports **responsive search ads** (RSAs) — Google's recommended search
ad format, where you supply 3–15 headlines and 2–4 descriptions and
Google permutes them at serve time — **video ads** for YouTube preroll
and bumper campaigns, and **Demand Gen video ads** for `DEMAND_GEN`
campaigns (both documented below). An `ad` carries **one** creative: an
RSA, a video ad, *or* a Demand Gen video ad.

<Aside type="note">
  Google requires a **minimum of 3 headlines and 2 descriptions** per
  RSA. bidsmith's linter warns if you supply fewer.
</Aside>

## Example

A responsive search ad with one pinned headline and one pinned
description:

```hcl
resource "google_ads_ad_group_ad" "summer_default_rsa" {
  ad_group = google_ads_ad_group.summer_default.id
  status   = "ENABLED"

  ad {
    name       = "Summer RSA"
    final_urls = ["https://example.com/summer"]

    responsive_search_ad {
      headline {
        text = "Summer Deals 2026"
        pin  = "HEADLINE_1"
      }

      headline {
        text = "Save On Summer Gear"
      }

      headline {
        text = "Free Shipping This Season"
      }

      description {
        text = "Limited-time offers across our summer range."
        pin  = "DESCRIPTION_1"
      }

      description {
        text = "Order today, get it before July."
      }

      path1 = "summer"
      path2 = "deals"
    }
  }
}
```

## Nested blocks

### `ad`

The wrapper around the actual creative. Bidsmith currently supports
exactly one `ad` block per `google_ads_ad_group_ad`.

<AttributeTable block={ad} headingLevel={4} />

### `responsive_search_ad`

A responsive search ad. Goes inside the `ad` block.

<AttributeTable block={rsa} headingLevel={4} />

#### `headline`

A single headline asset. Repeat the block 3–15 times. `text` is the
ad copy (≤ 30 characters); `pin` optionally locks the headline to a
specific position (`HEADLINE_1`, `HEADLINE_2`, or `HEADLINE_3`).

<AttributeTable block={headline} headingLevel={5} />

#### `description`

A single description asset. Repeat the block 2–4 times. `text` is the
ad copy (≤ 90 characters); `pin` optionally locks the description to
`DESCRIPTION_1` or `DESCRIPTION_2`.

<AttributeTable block={description} headingLevel={5} />

### `video_responsive_ad`

A **video ad** for a YouTube campaign (preroll / in-stream / bumper /
non-skippable). Goes inside the `ad` block, in place of a
`responsive_search_ad`. The `video` attribute references a
[`google_ads_youtube_video_asset`](./google_ads_youtube_video_asset/) —
the video that plays.

```hcl
resource "google_ads_youtube_video_asset" "brand_12s" {
  youtube_video_id = "dQw4w9WgXcQ"
}

resource "google_ads_ad_group_ad" "preroll" {
  ad_group = google_ads_ad_group.instream.id
  status   = "PAUSED"

  ad {
    name       = "Preroll 12s"
    final_urls = ["https://example.com/?utm_source=youtube"]

    video_responsive_ad {
      video           = google_ads_youtube_video_asset.brand_12s.id
      headlines       = ["Block Ads & Trackers"]
      long_headlines  = ["Ghostery blocks ads and trackers on every site"]
      descriptions    = ["Install the free privacy extension in one click."]
      call_to_actions = ["Install"]
    }
  }
}
```

The ad group must be a video type (`VIDEO_TRUE_VIEW_IN_STREAM`,
`VIDEO_BUMPER`, `VIDEO_NON_SKIPPABLE_IN_STREAM`, …) and its campaign
must be `advertising_channel_type = "VIDEO"`.

<Aside type="caution" title="bidsmith does not upload video, and does not apply video creatives yet">
  The video must **already be published on YouTube** — bidsmith
  references it by id and cannot upload video files. And while `plan` /
  `apply` manage the campaign scaffold (budget, targeting, status, final
  URLs), they do **not** create or update the video ad creative on the
  live account yet. Build the video ad in the Google Ads UI, then pull it
  into your `.bid` files with `bidsmith refresh`. The CLI warns you about
  both limits whenever a configuration includes video. See
  [`google_ads_youtube_video_asset`](./google_ads_youtube_video_asset/)
  for the full workflow.
</Aside>

<AttributeTable block={video} headingLevel={4} />

### `demand_gen_video_responsive_ad`

The creative a **Demand Gen** campaign runs
(`advertising_channel_type = "DEMAND_GEN"`). It's a distinct ad type
from `video_responsive_ad`: `videos` is a **list** of
[`google_ads_youtube_video_asset`](./google_ads_youtube_video_asset/)
references, and it adds `breadcrumb1` / `breadcrumb2`.

```hcl
resource "google_ads_youtube_video_asset" "shorts" {
  youtube_video_id = "dQw4w9WgXcQ"
}

resource "google_ads_ad_group_ad" "shorts_ad" {
  ad_group = google_ads_ad_group.demand_gen.id
  status   = "ENABLED"

  ad {
    name       = "Ad 1"
    final_urls = ["https://example.com/?utm_source=youtube"]

    demand_gen_video_responsive_ad {
      videos         = [google_ads_youtube_video_asset.shorts.id]
      headlines      = ["Block Ads & Trackers Free"]
      long_headlines = ["Block ads, trackers and cookie popups across the web"]
      descriptions   = ["Add the free privacy extension to your browser."]
      breadcrumb1    = "Adblocker"
      breadcrumb2    = "Browser"
    }
  }
}
```

The most common use is **adopting** a Demand Gen campaign you built in
the Google Ads UI — see
[Adopt an existing campaign](../../recipes/adopt-existing-campaign/).
`bidsmith pull` selects the Demand Gen creative and the campaign
round-trips through `export`.

<Aside type="caution" title="Creative is UI-managed; call-to-actions do not round-trip">
  As with video ads, bidsmith round-trips the Demand Gen creative for
  representation but `plan` / `apply` manage only the campaign scaffold —
  they do **not** create or update the creative on the live account. The
  video must already exist on YouTube. Note that `call_to_actions` come
  back from the Google Ads API as **asset references** rather than inline
  text, so they do not populate on a round-trip.
</Aside>

## Reusing one body across ad groups

When the *same* ad runs in every ad group of a campaign, you don't have
to paste the `ad {}` body into each `google_ads_ad_group_ad`. Declare
the body once in a top-level `ad_template "name" { … }` block — its body
is exactly an `ad {}` body — and attach it with `template =
ad_template.<name>` in place of the inline `ad {}` block:

```hcl
ad_template "ublock_rsa" {
  final_urls = ["https://ghostery.info/ublock?utm_term={keyword}"]
  responsive_search_ad {
    headlines    = ["uBlock Gone? Try Ghostery", "uBlock Replacement Found", "Switch from uBlock Now"]
    descriptions = ["Blocks ads, trackers & popups. Manifest V3 ready.", "The privacy suite millions trust."]
    path1        = "ublock"
    path2        = "ghostery"
  }
}

resource "google_ads_ad_group_ad" "replacement_rsa" {
  ad_group = google_ads_ad_group.replacement.id
  status   = "ENABLED"
  template = ad_template.ublock_rsa
}

resource "google_ads_ad_group_ad" "chrome_rsa" {
  ad_group = google_ads_ad_group.chrome.id
  status   = "ENABLED"
  template = ad_template.ublock_rsa
}
```

Each ad stays its own resource with its own address, so adopting a
template on an account that's already live is a no-op `plan` — the
expanded body is identical to what was there before. A template declared
in one file can be referenced from any other (same resolution as
resources), so a body shared across campaigns lives in one place.

<Aside type="note">
  A `google_ads_ad_group_ad` needs **exactly one** of an inline `ad {}`
  block or a `template`. Setting both, or neither, is a validate-time
  error. The template's headlines and descriptions are linted at the
  `ad_template` declaration, so the 3-headline / 2-description minimum is
  still enforced.
</Aside>

### Overriding part of a template

Most templates are split apart only because the landing page differs —
the headlines and descriptions are identical. Instead of forking the
template, keep one and override the bits that change at the reference.
Set `final_urls`, `path1`, or `path2` directly on the
`google_ads_ad_group_ad`; they take precedence over the template's
values, and anything you leave unset is inherited:

```hcl
ad_template "ublock_rsa" {
  responsive_search_ad {
    headlines    = ["uBlock Gone? Try Ghostery", "uBlock Replacement Found", "Switch from uBlock Now"]
    descriptions = ["Blocks ads, trackers & popups. Manifest V3 ready.", "The privacy suite millions trust."]
    path2        = "ghostery"
  }
}

resource "google_ads_ad_group_ad" "chrome_rsa" {
  ad_group   = google_ads_ad_group.chrome.id
  template   = ad_template.ublock_rsa
  final_urls = ["https://ghostery.info/chrome?utm_term={keyword}"]
  path1      = "chrome"
}

resource "google_ads_ad_group_ad" "safari_rsa" {
  ad_group   = google_ads_ad_group.safari.id
  template   = ad_template.ublock_rsa
  final_urls = ["https://ghostery.info/safari?utm_term={keyword}"]
  path1      = "safari"
}
```

A template that's meant to be URL-agnostic can omit `final_urls`
entirely, as above — but then every reference **must** supply its own,
or `validate` flags it. Overrides only apply on top of a `template`;
with an inline `ad {}` block, set these fields inside the block instead.
