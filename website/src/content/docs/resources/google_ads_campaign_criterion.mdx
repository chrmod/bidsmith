A **campaign criterion** is targeting that applies to a whole campaign:
negative keywords (excluded across every ad group), geo targets (which
locations your ads can show in), language targets, proximity
(latitude / longitude radius around a point), and device bid
adjustments (spend more or less — or nothing at all — on a device type).

<Aside type="tip">
  For plain *positive* country and language targeting, prefer the inline
  [`languages` / `locations`](./google_ads_campaign/#geo-and-language-targeting)
  lists on the campaign — `locations = ["US"]` reads far better than a
  `location {}` block per country, and round-trips identically. Reach for
  an explicit `google_ads_campaign_criterion` for the things the inline
  form deliberately leaves out: negative keywords, negative (excluded)
  locations, proximity, and cities you'd rather keep as a separate block.
</Aside>

## Example

Block negative keywords campaign-wide:

```hcl
resource "google_ads_campaign_criterion" "summer_negatives" {
  campaign = google_ads_campaign.summer_search.id
  status   = "ENABLED"

  negative_keyword {
    text       = "free"
    match_type = "BROAD"
  }

  negative_keyword {
    text       = "diy"
    match_type = "BROAD"
  }

  negative_keyword {
    text       = "used"
    match_type = "BROAD"
  }
}
```

Or, more compactly, with a `negative_keywords` list (optionally fanned
out across `match_types`):

```hcl
resource "google_ads_campaign_criterion" "summer_negatives" {
  campaign = google_ads_campaign.summer_search.id
  status   = "ENABLED"

  negative_keywords {
    match_type = "BROAD"
    texts      = ["free", "diy", "used"]
  }
}
```

Target the United States (geo target constant `2840`):

```hcl
resource "google_ads_campaign_criterion" "summer_geo_us" {
  campaign = google_ads_campaign.summer_search.id
  status   = "ENABLED"

  location {
    geo_target_constant = "geoTargetConstants/2840"
  }
}
```

Target Polish-speaking users (language constant `1030`):

```hcl
resource "google_ads_campaign_criterion" "summer_lang_pl" {
  campaign = google_ads_campaign.summer_search.id
  status   = "ENABLED"

  language {
    language_constant = "languageConstants/1030"
  }
}
```

Show only within 15 km of central Warsaw:

```hcl
resource "google_ads_campaign_criterion" "summer_warsaw" {
  campaign = google_ads_campaign.summer_search.id
  status   = "ENABLED"

  proximity {
    latitude     = 52.229675
    longitude    = 21.012228
    radius       = 15
    radius_units = "KILOMETERS"
  }
}
```

Stop showing on mobile entirely — a `bid_modifier` of `0` is a −100%
adjustment, so nothing spends there. This is the classic setup for a
browser-extension campaign, where installs only happen on desktop and
mobile clicks are wasted budget:

```hcl
resource "google_ads_campaign_criterion" "no_mobile" {
  campaign     = google_ads_campaign.extension_installs.id
  bid_modifier = 0.0

  device {
    type = "MOBILE"
  }
}
```

Or nudge bids rather than switch a device off — bid 20% more on desktop
(`bid_modifier = 1.2`) and 30% less on tablets (`bid_modifier = 0.7`):

```hcl
resource "google_ads_campaign_criterion" "desktop_boost" {
  campaign     = google_ads_campaign.summer_search.id
  bid_modifier = 1.2

  device {
    type = "DESKTOP"
  }
}

resource "google_ads_campaign_criterion" "tablet_trim" {
  campaign     = google_ads_campaign.summer_search.id
  bid_modifier = 0.7

  device {
    type = "TABLET"
  }
}
```

## Nested blocks

### `keyword`

A positive keyword scoped to the entire campaign. Uncommon — usually
keywords live at ad-group scope. Use this only if you genuinely want a
keyword to apply across every ad group.

<AttributeTable block={keyword} headingLevel={4} />

### `negative_keyword`

A negative keyword that excludes searches campaign-wide. Repeat the
block to list many. The most common use of `google_ads_campaign_criterion`.

<AttributeTable block={negative_keyword} headingLevel={4} />

### `negative_keywords`

The compact form: a list of `texts` fanned out across a single
`match_type` or a list of `match_types`. One block stands in for many
`negative_keyword` blocks. Set exactly one of `match_type` or `match_types`.

<AttributeTable block={negative_keywords} headingLevel={4} />

### `location`

A geo target — restricts where your ads can show. Use Google's
[geo target constants](https://developers.google.com/google-ads/api/data/geotargets)
(e.g. `geoTargetConstants/2840` for the United States).

<AttributeTable block={location} headingLevel={4} />

### `language`

A language target — restricts what user-language settings can see your
ads. Use Google's
[language constants](https://developers.google.com/google-ads/api/data/codes-formats#languages)
(e.g. `languageConstants/1030` for Polish, `languageConstants/1000` for English).

<AttributeTable block={language} headingLevel={4} />

### `proximity`

A circular radius target — ads only show to users within `radius` of
the given (latitude, longitude). Use for hyperlocal campaigns.

<AttributeTable block={proximity} headingLevel={4} />

### `device`

A device bid adjustment. Pair a `device` block with the resource's
`bid_modifier` attribute to spend more, less, or nothing on a device
type. `type` is one of `MOBILE`, `DESKTOP`, `TABLET`, `CONNECTED_TV`,
or `OTHER`.

`bid_modifier` is a multiplier on your bid: `1.0` is no change, `1.25`
bids 25% more, `0.5` bids 50% less, and `0.0` is a −100% adjustment that
opts the device out completely. Editing the modifier later is an
in-place update — Google Ads keeps the campaign's history.

<AttributeTable block={device} headingLevel={4} />
