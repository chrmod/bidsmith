title: Serve only the extensions you declared
description: Turn on ownership so a campaign's sitelinks, callouts, and snippets are exactly the ones in your .bid — and anything added elsewhere is removed.
---

Your file says a campaign has four sitelinks. The live ad shows eight.
The other four came from somewhere else — added in the Google Ads UI,
inherited from an account-level extension that attaches to *every*
campaign, or generated by Google.

By default bidsmith leaves them alone: it only reconciles what it can
prove it manages. This page turns that around, so that within a scope
you name, **the file is the complete list** and anything else is
removed.

## A campaign owns the kinds it declares

Ownership is not a flag you pass — it's what declaring something means.
The moment a campaign declares one sitelink, bidsmith treats that
campaign's sitelinks as yours:

```hcl
resource "google_ads_campaign_asset" "checkout_sitelinks" {
  campaign = google_ads_campaign.checkout.id
  assets = [
    google_ads_sitelink_asset.free_delivery.id,
    google_ads_sitelink_asset.size_guide.id,
  ]
}
```

```
bidsmith plan .
```

```
google_ads_campaign.checkout (removed sitelink "Gift cards")   - destroy
google_ads_campaign.checkout (removed sitelink "Our story")    - destroy

Plan: 0 to create, 0 to update, 2 to destroy, 1 to adopt, 12 unchanged.
```

The scope is one **kind** of extension on one campaign. Declaring
sitelinks says nothing about that campaign's callouts, and nothing at
all about any other campaign. A campaign that declares no sitelinks
keeps every sitelink it has.

<Aside type="tip">
  The `~ adopt` row in that plan writes a `bidsmith:owns` label on the
  campaign. It's what lets you later delete the *last* sitelink block
  and still have the live ones removed — without it, an empty file
  would read as "not managed here" and the sitelinks would be stranded.
</Aside>

The same holds for an ad group with
[`google_ads_ad_group_asset`](/bidsmith/resources/google_ads_ad_group_asset/),
and for the [`callouts`](/bidsmith/resources/google_ads_campaign/) and
`structured_snippet` shorthands on a campaign.

## The account level has to be asked for

Extensions attached to the **account** rather than to a campaign show up
under every campaign you run — a generic "Shop now" sitelink appearing
beneath an ad about something else entirely. Removing one changes every
campaign at once, so bidsmith never does it because a block happens to
exist. Say so in the `provider` block:

```hcl
provider "google_ads" {
  customer_id = "1234567890"
  owns        = ["sitelinks", "callouts"]
}
```

```
account (removed account-level sitelink "Shop now")     - destroy
account (removed account-level callout "Free returns")  - destroy
```

Now the account-level sitelinks and callouts are exactly the
[`google_ads_customer_asset`](/bidsmith/resources/google_ads_customer_asset/)
blocks in your files — including none at all, which is the usual answer
once each campaign carries its own.

`owns` accepts `sitelinks`, `callouts`, `structured_snippets`, and
`calls`. Anything you leave out is untouched.

## Getting there without breaking anything

<Steps>

1. **Adopt first.** Anything you want to *keep* has to be declared
   before ownership is on, or the first apply removes it — see
   [Adopt sitelinks and callouts you already have](./adopt-sitelinks-and-callouts-you-already-have/).

2. **Plan and read the destroys.** `bidsmith plan .` lists every
   removal by what it puts on the page (`removed sitelink "Gift
   cards"`), not by an id. Nothing has been sent to Google Ads.

3. **Delete the blocks you don't want**, keep the ones you do, and plan
   again until the destroy list is exactly what you meant.

4. **Apply.** `bidsmith apply .` shows the same list and asks for
   confirmation before anything is removed.

</Steps>

## Two things prune will not remove

Some removals the Google Ads API rejects outright, and one rejected
operation fails the whole batch with it. bidsmith checks for these
before sending anything, skips them, and says so — the rest of your
changes still apply:

```
plan: warning: google_ads_campaign.checkout: live sitelink "Firefox too" was
attached by Google's asset automation, not by anyone — removing it only makes
Google reattach it, so it is left alone. Turn automatically created assets off
for the account to stop it serving.

Plan: 0 to create, 0 to update, 2 to destroy (1 skipped), 12 unchanged.
```

- **Assets Google created** (`AUTOMATICALLY_CREATED` — dynamic
  sitelinks, auto headlines, a business name). While asset automation is
  on for the account, Google puts them back, so removing them would show
  up as the same destroy on every plan forever. Turn the automation off
  first — see [Stop Google writing your ad
  copy](./stop-google-writing-your-ad-copy/) for which half of it a
  `.bid` can declare and which half is a switch in the Google Ads UI.
- **Anything on a Video campaign.** The API cannot mutate YouTube
  campaigns at all, extensions included.

The same skip-and-warn applies to a device criterion nobody declared:
Google refuses to remove those, so bidsmith reports the drift rather
than sending an operation that would sink the batch.
